# Instructions for AI agents

This file is for coding agents that integrate `pesa_checkout` into a
Flutter app or that change this repository. Humans: read README.md first.

## What this package is

- pub.dev package `pesa_checkout`. Native card fields for a Pesa intent.
- 3-D Secure in Custom Tabs (Android) or `SFSafariViewController` (iOS)
  through `url_launcher`. SPKI-pinned TLS to `checkout.pesa.co`.
- No web views. Android minSdk 24. iOS 15.

## Hard rules

1. Never log, store or send `clientSecret` anywhere except to the SDK.
2. Never fulfil an order from `CheckoutResult`. The server fulfils only on
   `intent.state_changed` or `GET /v1/intents/{reference}`.
3. Never put the Pesa API key in the app.
4. Never keep `CardDetails` after `payWithCard` returns. Call
   `form.clear()` in `finally`.
5. Never ship a release build with an empty `pins` list.
6. Never add a web view for card entry.

## Integrate into an app (steps in order)

1. Server: create the intent with `POST /v1/intents`. Set `returnUrl` to
   an https app link of the app. Return `id` and `clientSecret` to the
   app.
2. App: `flutter pub add pesa_checkout`. On Android 11+, add the
   `<queries>` block from README.md to `AndroidManifest.xml`.
3. App: `final checkout = PesaCheckout(pins: const ['<pin 1>', '<pin 2>'])`.
   Keep one instance.
4. App: `final session = await checkout.session(intentId, clientSecret)`
   to get the amount, currency, merchant name and `needsEmail`.
5. App: show `PesaCardForm(controller: form, needsEmail: session.needsEmail)`
   inside `PesaSecureScreen`. Add `PesaPayButton`.
6. App: on pay, `form.details()`, then
   `await checkout.payWithCard(intentId, clientSecret, card, email: form.emailText)`.
   Then `form.clear()` in `finally`.
7. App: show the outcome from `r.isSuccess`, `r.isDeclined` and
   `r.failureReason`. Catch `PesaCheckoutException` and switch on `code`.
8. Server: handle the `intent.state_changed` webhook. Fulfil on
   `settled`, or on `authorized` when the merchant captures by hand.

A full example is in `README.md` and `example/`. A skill with the same
steps is in `skills/pesa-checkout-flutter/SKILL.md`.

## Change this repository

Layout:

| Path | Content |
|---|---|
| `lib/pesa_checkout.dart` | Public exports. |
| `lib/src/client.dart` | `PesaCheckout`: session, pay, poll, challenge. |
| `lib/src/models.dart` | Session, attempt, result, exception. |
| `lib/src/card.dart` | Card validation, `CardDetails`. |
| `lib/src/pinning.dart` | SPKI pin check on the TLS socket. |
| `lib/src/secure_screen.dart` | `PesaSecureScreen`. |
| `lib/src/l10n/` | `PesaCheckoutStrings`: one map per language. Add every new user-visible string to en, fr and zh-Hans; fr-CA lists only its Québec overrides. |
| `lib/src/widgets/` | `PesaCardForm`, `PesaPayButton`. |
| `android/`, `ios/` | Platform plugin code for the secure screen. |
| `example/` | Example app. |
| `test/` | Widget and unit tests. `test/fixtures/` is generated by `make fixtures` and not committed. |
| `.github/workflows/ci.yml` | Analyze and test on push and PR. |
| `.github/workflows/release.yml` | pub.dev publish on a signed `v*` tag. |

Commands:

```
flutter pub get
flutter analyze
make test          # generates test/fixtures/ (self-signed localhost TLS key) then runs flutter test
```

Rules for changes:

- Run `flutter analyze` and `make test` before you finish. Both must
  pass with no warnings.
- Add a test in `test/` for every behaviour change.
- Keep the public API in `lib/pesa_checkout.dart`. Export only what the
  merchant app needs.
- Keep error codes in step with pesa-ios and pesa-kotlin. The three SDKs
  share one error vocabulary.
- Add a line to `CHANGELOG.md` under "Unreleased" for every user-visible
  change. pub.dev shows this file.
- Do not add dependencies without a reason in the PR description.
- Do not edit `.github/allowed_signers` or `.github/verify-tag.sh`.
- Do not create tags. A maintainer signs and pushes release tags.
- Do not add `Co-Authored-By` or similar trailers to commit messages.

## Terms

| Term | Meaning |
|---|---|
| intent | A payment the merchant server created on the Pesa API. |
| client secret | A per-intent token for the app. It is not the API key. |
| attempt | One try to pay an intent. |
| checkout service | `checkout.pesa.co`. It takes the card from the SDK. |
| gateway | The Pesa API that owns intents and sends events. |
| pin | Base64 SHA-256 of the checkout service's SubjectPublicKeyInfo. |
